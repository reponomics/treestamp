# ADR 0003: Generated testing plan

Status: superseded by [ADR 0007](0007-focused-generated-testing.md). The implementation plan and results below describe the earlier approach.

Review: the proposal was checked against the codec, document, session, hosted request, and browser modules before implementation, and the resulting amendments received an independent review that verified their claims against the code. That review corrected the definition of unrepresentable entries and the browser identity domain, refined the server-state and fabricated-commit requirements, and found two hosted responses that failed with HTTP 500 (both fixed with regressions). [Revision](#revision) lists each amendment. An independent review of the implementation led to further fixes, recorded in the results below.

## Alternatives

| Approach | Strength here | Cost and limitation |
| --- | --- | --- |
| Hypothesis in pytest | Generate valid and nearly valid trees and requests; check semantic properties; minimize failing examples | Generators and assertions must encode the intended contract. Does not exercise JavaScript or constitute a browser security scan. |
| Atheris | Coverage-guided mutation of raw document bytes and parser inputs; useful for unexpected exceptions and pathological syntax | Separate instrumentation, harness, corpus, and process limits. Upstream lists Linux/macOS, while our ordinary test matrix also includes Windows. Random byte input needs representative seeds to reach deeper parsing. |
| Staged combination | Hypothesis first; add an isolated Atheris parser campaign later if coverage gaps justify it | Wider eventual coverage, but two testing paths to maintain. No second engine in the initial change. |

Recommendation: Hypothesis first, with the staged combination available later. Keep the dependency development-only and locked with the existing uv workflow. Atheris is a credible alternative, not a requirement for the first increment. Scorecard recognition is not an acceptance criterion or a promised result.

Sources: [Atheris](https://github.com/google/atheris), [Hypothesis stateful tests](https://hypothesis.readthedocs.io/en/latest/stateful.html), [Hypothesis external-fuzzer integration](https://hypothesis.readthedocs.io/en/latest/how-to/external-fuzzers.html).

## Initial implementation

1. **Request validation.** Generate bounded arbitrary JSON and valid operation/placement envelopes with one field mutated. Check schema parsing separately from service execution. Expected malformed input must receive a documented domain rejection; unexpected exceptions fail the test. Accepted requests still must satisfy source and server-tree constraints. A fabricated commit, even when changed consistently in both request and envelope, must not authorize a GitHub fetch. Operation and placement requests make no upstream request at all, whatever the commit or outcome. A preview or browse request pinned to a commit that is not the current default-branch head may read repository metadata and resolve the default branch, which is how it detects that the commit is not current, but no request may name the pinned commit and no tree or blob may be read. Because the fake serves any object in its fixture repository, draw pinned commits from older real commits and object ids as well as random hexadecimal, and assert on the transport's request log rather than on a 404. Use controlled snapshots and fake transports, never live GitHub. The hosted API keeps no curation state between requests. A rejected operation or placement leaves cached records, blobs, and expiry unchanged, makes no upstream request, and the accepted request replays to the same response afterwards. Rejected requests consume rate-limit tokens by design, so generated request tests disable rate limits and never accept `rate_limited` as an outcome. The application maps an escaped `MarkerError` to a 422 `curation` response, which can hide an unexpected failure; generated requests against a fixture whose entries are all representable must not produce it. `/api/export/svg` is covered by arbitrary-JSON parsing only. In the core, a rejected session operation must leave the session's captured state unchanged.
2. **Document serialization.** Generate a supported subset of small trees, then vary styles, line endings, annotations, quoted names, Unicode, encoded Git bytes, and symlinks. Require successful serialization and parsing with the intended semantic result, plus byte-for-byte preservation outside the managed document region. Separately test unsupported inputs. Do not catch rendering errors and call them success for supported inputs: the renderer already checks its own parse roundtrip. Some entries cannot be represented in the current printed format. Representability depends on printed text, in which trailing whitespace is escaped, not on the raw name or target: a symlink target printed as `null` is indistinguishable from an absent target; a symlink row whose arrow and printed target together contain the annotation delimiter (two spaces, `#`, space), such as a target beginning with ` # `, splits at the wrong place; a symlink or gitlink whose name is not registered as special and ends in ` ->` or `  #` reads as a different entry; and an annotated row whose printed head ends in `  #`, such as a file named `a  #` or a symlink target of ` #`, splits its annotation early. A target ending in `  # ` is representable because its trailing space is escaped. Source-tree cases fail preflight; annotation cases fail when the note is applied. A test-owned predicate encodes these rules on printed text. Properties require a `MarkerError` from the renderer exactly when the predicate matches and a faithful roundtrip otherwise, so an unexpected rejection and an over-broad predicate both fail.
3. **Session transport.** Generate valid curation over small snapshots and verify JSON serialization/restoration preserves annotations, folding, and hidden state. Compare state and subsequent observable behavior. Keep this separate from document roundtrips: documents intentionally omit some transient session state. Account for specified normalization and intentionally allowed hidden paths that are no longer tracked.
4. **Browser input and rendering.** Include this in the initial increment. Use bounded Hypothesis-generated JSON/text cases against the actual `logic.js` and `draft.js` modules, without reimplementing their decoders in Python or adding a second generation library. The Python tests drive one persistent Node worker per test module, which imports the real modules and answers one JSON request per line; the worker is not a `*.test.mjs` file, so `node --test` does not collect it. The worker returns exceptions as data, is restarted if it exits, and has a generous per-request I/O timeout, because per-example deadlines are disabled. Requests and responses are ASCII-escaped JSON. These tests belong to the hosted Python suite, which therefore requires Node 24 or later (the version in `.nvmrc`): they skip with an explicit reason when a suitable `node` is absent locally and fail when `CI` is set. The coverage workflow installs Node from `.nvmrc`, as the hosted CI job does. Exercise URL path/query/fragment, base64/UTF-8 decoding, nested saved settings, and localStorage records. Supported states must preserve identity; invalid states must lead to a controlled error or ignored draft, not an uncaught startup exception or unintended navigation. A controlled error is a null or false result, or a thrown `Error` carrying a user-facing message; a `TypeError` or `RangeError` is a failure. The identity domain is JSON without `-0` or non-finite numbers, which JSON encoding changes; lone surrogates are included, because `JSON.stringify` escapes them before UTF-8 encoding. The Python harness also restricts numbers to integers within ±(2^53 − 1), which the Python–Node boundary would otherwise change. Generated keys include `__proto__`, and the worker checks that `Object.prototype` is unchanged after each request. Include explicit length/depth boundaries; a server request-size limit does not protect browser decoding before a request.

Use a small browser regression corpus through the existing local service and fake GitHub to exercise successful restore and server rejection. The corpus uses its own fixture repository and service pair, so existing browser fixtures and assertions are unaffected. Payload paths are added through the Git index, because filesystems cannot hold every such name. Include HTML/SVG/event-handler payloads in notes, paths, query errors, and transfer conflict messages, plus crafted external or script-scheme URLs. Assert literal text and absence of attacker-created elements/attributes, executable sentinels, unexpected requests, and navigation; checking only for an alert is insufficient. Cover editor, source browser, Markdown output, and placement/error surfaces. Retain normal Content Security Policy checks, and repeat selected rendering cases with CSP bypassed only in the test browser to verify safe rendering independently of CSP. Do not weaken production headers. Supplement real server flows with explicitly labeled synthetic-response tests for URL-sink defense; those tests do not establish that a forged server response is attacker-reachable. Response validation must accept a repository link only if it equals `https://github.com/{owner}/{name}` for the response's own repository, and a history address only if the permalink's path equals `/{owner}/{name}@{commit}` for the response's own identity; the permalink's origin is not compared, because a configured public base URL makes it absolute on another origin. A forged permalink whose path begins with `//` currently yields a protocol-relative address, and `history.replaceState` then throws after the page has already replaced its accepted editor and rows.

Read-only inspection found text sinks throughout these surfaces, static HTML page responses, JSON API responses, and a repository link constructed server-side from validated GitHub identifiers. No working XSS exploit was identified. A malformed captured state with `curation.settings.root = null` passes the browser's shallow startup guard and throws in `valuesFromSettings`/`displayPath` before server validation; a Node reproduction confirms the exception. Add a regression and correct this startup handling during implementation, with one pure captured-session validator in `logic.js` shared by the fragment startup path and the localStorage draft path; it checks the source paths and settings shape before any display conversion or editor assignment. Settings that are missing, not objects, or contain a root that is null, missing, or a malformed `git_bytes` value all throw today. Check the analogous localStorage journey as well: an unusable draft currently passes `draftForLocation`, and the exception occurs when the user resumes it. The draft store applies the same validator, so an unusable draft is ignored and never offered. The generated property is that whenever the validator accepts a captured state, `valuesFromSettings` and `displayPath` on its source root and document do not throw; Playwright regressions cover the fragment and draft journeys with no `pageerror`. This is a robustness finding, not demonstrated script execution.

Construct expected path/kind/annotation facts from the generated source model before rendering, and compare parsed semantics to those facts. Include representative CRLF and BOM cases in the independent prefix/suffix assertions. Cross actual JSON encoding/decoding in session transport tests and preserve exact byte-path identities. Do not build expected results by calling the same transformation being tested. Each generated example gets fresh mutable session/cache state; pytest fixture reuse must not leak edits between examples. Rejected service requests must not alter accepted session state or cached snapshot contents.

## Execution and failure handling

- Integrate short runs into ordinary core and hosted pytest checks; add documented Makefile targets for focused and extended local runs. Start with roughly 100 examples per property and measure runtime before choosing final budgets. Bound tree size, JSON depth/width, text length, and operation count. Each suite registers Hypothesis profiles in its `conftest.py`, derived from Hypothesis's default profile: `ordinary` for ordinary runs and `extended`, selected with `HYPOTHESIS_PROFILE=extended`. Both disable the per-example deadline, which is a wall-clock assertion, and print reproduction blobs. Hypothesis automatically loads a derandomized profile when it detects CI; loading `ordinary` explicitly, with `derandomize=False`, is what keeps CI from running one fixed seed, and deriving it from the default profile keeps local and CI settings otherwise identical.
- Use process/CI timeouts for runaway execution. Small generated inputs do not establish resistance to resource exhaustion: retain explicit request-size boundaries and add focused depth/length boundary cases where missing. Avoid fragile per-example wall-clock assertions.
- Keep Hypothesis's local example database (already ignored), report reproducible failures, and turn minimized discoveries into committed regression examples. CI must not depend on an existing local database or a single fixed seed. Do not upload generated payloads from real user sessions.
- Catch only the expected rejection types at the relevant boundary. Unexpected exceptions, hangs, or invariant violations fail the run. Do not suppress findings by narrowing generators without establishing that the rejected input is outside the supported contract.
- Verify at least one property detects a temporary intentional defect, then remove the defect. Run focused properties, relevant regression suites, lint, type checks, lock validation, and documentation checks. Record example budgets and measured runtime.

## Results of the initial increment

Budgets: 100 examples per property in ordinary runs and 1,000 with `HYPOTHESIS_PROFILE=extended`, across 19 generated properties (6 core, 13 hosted, 8 of which are browser-decoding cases). The same files hold deterministic cases: a hosted type-swap sweep, explicit fragment length and depth boundaries, a tree depth limit, and one case per representability rule. The browser corpus has 11 cases. Measured on one Apple Silicon development machine: the generated tests take about 3 seconds in the core suite and 14 seconds in the hosted suite at the ordinary budget, and about 30 and 75 seconds at the extended budget; the corpus adds about 5 seconds to the browser suite. CI timings will differ.

Defects found and fixed, each with a committed regression:

| Finding | Found by | Fix |
| --- | --- | --- |
| A JSON path spelled as escapes of valid UTF-8 bytes (`\udcc2\udc80`) passed validation, then changed identity in documents and transport | Generated document property | `validate_path` accepts only the canonical decoding |
| A placement conflict on a byte path, and a config comment holding a non-UTF-8 byte, both produced HTTP 500 | Review of the amended plan | Escaped error details; retained region bytes that are not UTF-8 are rejected before caching |
| A captured session with undisplayable settings threw at startup, or on resuming a draft | Read-only inspection, confirmed in Node | Shared captured-session validator |
| A saved state nested deeply enough to overflow `JSON.stringify` left an unhandled rejection on restore | Generated browser boundary case | `decodeState` refuses states nested beyond 32 levels |
| A forged permalink could yield a protocol-relative history address, and a forged repository link any URL | Synthetic responses; implementation review (empty owner) | Both built from the response's own identity, validated as the service validates it |

Intentional defects, injected one at a time and then removed, were each detected: a shallow startup guard (browser startup property and Playwright regressions), unescaped trailing whitespace in printed names (document property), restore dropping untracked hidden paths (transport property), and a missing envelope revision type check (the hosted type-swap sweep on every run; random mutation found it in about half of extended runs before mutation was biased toward type swaps, which motivated the sweep). A cache read that renewed the snapshot lease is detected by the sweep; the implementation review found that a frozen test clock had hidden it, so the clock now advances between requests. Removing any clause of the representability predicate fails its parametrized case on every run, and the generated property alone in one to four of five runs. A control case shows that the corpus sentinels detect a payload that does execute when CSP is bypassed.

## Explicit follow-ups and limits

Browser coverage is deliberately bounded: generated pure JavaScript decoding cases plus a small real-browser injection corpus, not a general browser fuzzer or automated penetration test. Live infrastructure and distributed resource exhaustion remain outside this initial increment. The fragment is initially browser-only, but the app subsequently posts decoded state to the API; both direct DOM handling and JSON responses rendered into the DOM must be exercised. See [OWASP DOM XSS guidance](https://cheatsheetseries.owasp.org/cheatsheets/DOM_based_XSS_Prevention_Cheat_Sheet) and [MDN fragments](https://developer.mozilla.org/en-US/docs/Web/URI/Reference/Fragment).

Placement action-sequence testing is the next candidate: place/skip/undo, recursive directory moves, and explicit replacement conflicts. Define note-preservation rules that allow intentional skipping and replacement before writing those properties. Existing placement regression tests remain in force.

Representing the unrepresentable entries described above requires a printed-format change and its own compatibility decision. Until then, a selected subtree containing such entries cannot be opened, and such notes cannot be saved. Annotations follow Python's `str.isprintable()`, which rejects, for example, no-break spaces, zero-width joiners in emoji sequences, and code points unassigned in the running Python's Unicode database; committed regression examples avoid characters whose category differs across the supported Python versions.

Restoration onto a newer commit remains unimplemented and is not certified by these tests. A future implementation needs its own source/target transition properties. This work strengthens testing of current contracts; it is not a comprehensive security audit.

## Revision

Amendments to the original proposal, made after checking it against the code and revised after independent review:

| Area | Original wording | Amendment and reason |
| --- | --- | --- |
| Browser mechanism | "in batches ... through the existing Node runner" | A persistent Node worker driven by Python Hypothesis. `node --test` cannot host Hypothesis, and one process per example would dominate runtime. The hosted suite gains a Node 24 requirement, enforced in CI, and the coverage workflow installs Node. |
| Browser identity | "Supported states must preserve identity" | Defines the identity domain and a controlled error. The first amendment wrongly excluded lone surrogates; review showed that `-0` and non-finite numbers are what JSON encoding changes. |
| Startup fix | "correct this startup handling" | One validator shared by the fragment and localStorage paths, applied before the editor is assigned, so the journeys cannot diverge and an unusable draft is never offered. |
| Fabricated commit | "must not authorize a GitHub fetch" | No upstream request from operation or placement requests; pinned previews and browses read metadata and resolve the default branch by design but never name the pinned commit. Commits are drawn from real objects too, because the fake serves them. |
| Rejected requests | "must preserve the previously accepted state" | The hosted API keeps no curation state; rejected edits leave the cache, including expiry, unchanged and replay identically. Rate limiters are disabled in these tests because rejected requests consume tokens. Core sessions are checked directly. |
| Document subset | "supported subset" | Defines unrepresentable entries on printed text. The first amendment named only two targets; review found that one of them is representable and that names and annotated rows have further cases. |
| Execution | "roughly 100 examples" | `ordinary` and `extended` profiles derived from Hypothesis's default; deadlines disabled; explicit randomization overrides Hypothesis's derandomized CI profile. |
| Browser corpus | "existing local service and fake GitHub" | A separate fixture repository and service pair, so payload paths do not change other browser tests. |
| URL sinks | synthetic-response tests | The repository link and the history address must match the response's own identity. |
| Hosted responses | not covered | Review found two HTTP 500 responses caused by undecodable bytes: a config comment retained verbatim in the region, and a placement conflict question on a byte path. Both are fixed with regressions. |
